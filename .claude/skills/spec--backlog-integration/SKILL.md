# Backlog MCP連携スキル

Backlog MCPツールを使って課題の検索・取得・作成・更新・コメント操作を行うためのリファレンスです。
各ツールのパラメータ仕様は MCP ツールスキーマ自体を参照してください（ここでは重複させません）。

## 課題検索パターン

### キーワード検索

`keyword` は件名・説明文を対象に全文検索します。複数単語はスペース区切りでAND検索。

```json
{ "keyword": "認証エラー" }
{ "keyword": "タイムアウト 本番" }
```

### ステータス検索

| statusId | ステータス名 |
|---|---|
| 1 | 未対応 |
| 2 | 処理中 |
| 3 | 処理済み |
| 4 | 完了 |

未完了の課題: `{ "statusId": [1, 2] }`

### 担当者検索

自分の担当課題を検索する場合: `get_myself` でユーザーIDを取得 → `assigneeId` に指定。

### 過去の類似課題を探す

過去の課題は**クローズ済み**なので、`statusId` に `4`（完了）を含めないと結果が空になります。

```json
{ "keyword": "ログイン", "statusId": [1, 2, 3, 4] }
```

1. キーワードは**機能名・画面名・エラー文言**など短い語で当てる（長い説明文はヒットしない）
2. 候補が見つかったら `get_issue` で本文、`get_issue_comments`（`order: "asc"`）で時系列のやり取りを取得
3. 検証方法・再現手順・修正時の議論を拾い、後述の「課題要約テンプレート」で整理する

### 課題が見つからない時の対処法

1. キーワードを変える・短くする（例: 「エラーハンドリング改善」→「エラー」）
2. `projectId` で絞り込む、または `statusId: 4`（完了済み）を含めて検索範囲を広げる
3. `count: 100` で最大件数取得、`keyword` を省略して一覧確認

## 課題要約テンプレート

`get_issue` と `get_issue_comments` で取得した情報を以下の構成で要約します。

```
## 課題要約: {課題キー} {課題タイトル}

### 背景・経緯
### 目的・解決したい課題
### 要件・仕様（完了条件含む）
### 影響範囲
### 懸念点・リスク
### 現在のステータス
- ステータス: / 担当者: / コメント数: / 最終更新:
```

## よくある操作パターン

**課題の内容を調べて清書する場合:**
1. `get_issue` で本文取得 → `get_issue_comments`（`order: "asc"`）で時系列コメント取得
2. 上記テンプレートで要約・清書
3. `add_issue_comment` または `update_issue` で投稿

**担当課題の進捗確認:**
1. `get_myself` でユーザーID取得
2. `get_issues` に `assigneeId` + `statusId: [1, 2]` を指定して一覧取得
