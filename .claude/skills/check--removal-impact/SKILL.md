# 機能撤去・文言影響範囲チェック

撤去対象のキーワード（例:「友だち追加ボタン」）を起点に、コードベース・規約/マニュアル・画面文言定義を横断検索し、ヒット箇所を「削除対象」「要修正」「残す（要確認）」に仕分けしたチェックリストを生成するスキルです。

**実行タイミング**: PRを出す前・課題を完了にする前に必ず実行し、消し漏れ・直し漏れを防ぐ。

## 人間 / AI 役割分担

| 役割 | 担当 |
|------|------|
| **撤去範囲の最終判断**: どこまで消すか・規約改訂を伴うかを決定する | 人間 |
| **「残す（要確認）」項目の判断**: 機械的に判定できないヒット箇所の扱いを決める | 人間 |
| **規約・マニュアル改訂の承認**: ユーザー向け文書の変更内容を承認する | 人間 |
| **キーワード展開**: 表記ゆれ・英語識別子・コンポーネント名へ展開する | AI |
| **横断検索**: 3カテゴリ（コード・文書・文言定義）を漏れなくgrepする | AI |
| **仕分けの一次判定**: ヒット箇所の前後を読み3分類に仕分ける | AI |
| **チェックリスト生成**: 仕分け結果を一覧化してチャットに出力する | AI |

---

## 仕分け基準

| 分類 | 基準 | 例 |
|------|------|-----|
| **削除対象** | 撤去機能そのものの実装・テスト・文言。機能と共に消えるべきもの | 機能のコンポーネント/関数/テスト、機能専用の文言キー、機能専用のマニュアルページ |
| **要修正** | 撤去機能に言及するが、それ自体は残るもの。書き換えが必要 | 周辺機能の説明文中の言及、規約の該当条項、他画面からの導線・リンク、機能有無の条件分岐 |
| **残す（要確認）** | 機械的に判断できないもの。人間の確認が必要 | 同名だが別機能の可能性があるもの、過去バージョンの記述、CHANGELOG・リリースノート |

**判断に迷ったら「残す（要確認）」に倒す**（誤削除より確認漏れの方が復旧しやすい）。

---

## 検索対象カテゴリ

| カテゴリ | 対象 | 典型的な場所 |
|---------|------|-------------|
| ① コードベース | 実装・テスト・条件分岐 | `src/`, `app/`, `*.test.*`, `*.spec.*` |
| ② 規約・マニュアル | 利用規約、操作マニュアル、ヘルプ | `docs/`, `terms/`, `manual/`, `help/` 配下のMarkdown |
| ③ 画面文言定義 | i18nリソース、文言定数 | `i18n/`, `locales/`, `ja.json`, `messages.ts` 等 |

場所はプロジェクトごとに異なる。初回実行時は Glob で候補ディレクトリを特定し、②③の場所が不明な場合は仮定せず人間に確認する。

## Step by Step ガイド

### Step 1: キーワード展開 (Keyword Expansion)

**目的**: 撤去対象を表すすべての表記を洗い出し、検索漏れを防ぐ

**AIのタスク**: 受け取ったキーワードを以下の観点で展開する

- 日本語の表記ゆれ: `友だち追加` / `友達追加` / `ともだち追加`
- 英語識別子: `addFriend`, `friend_add`, `FriendAddButton`, `add-friend`
- コンポーネント名・文言キー・機能フラグ名: `friendAddEnabled`, `feature.friend_add`
- 略称・社内呼称があれば人間に確認する

展開結果を提示し、人間が追加・除外を指示できるようにする。

---

### Step 2: 横断検索 (Cross Search)

**目的**: 展開した全キーワードで3カテゴリを漏れなく検索する

**AIのタスク**: キーワードごとに以下を実行

```bash
# ① コードベース（実装・テスト）
rg -n "<keyword>" -g "!node_modules" -g "!dist" -g "!build" -g "!coverage"

# ② 規約・マニュアル（Markdown）
rg -n "<keyword>" -t md

# ③ 画面文言定義（i18n・文言定数）
rg -n "<keyword>" -g "*.json" -g "*locales*" -g "*i18n*"

# 過去に消された言及の確認（復活防止・経緯把握）
git log --oneline --all -S "<keyword>"
```

日本語キーワードは大文字小文字の区別が不要だが、英語識別子は `-i` を付けて検索する。
隠しディレクトリ（`.github/` 等）配下も対象にする場合は `--hidden -g "!.git"` を追加する（rg はデフォルトで隠しファイルをスキップする）。

---

### Step 3: 仕分け (Triage)

**目的**: 全ヒット箇所を3分類に仕分ける

**AIのタスク**: 各ヒットの前後コンテキストを読み（`rg -C 3` またはファイルを開く）、仕分け基準テーブルに従って分類する

- ヒット箇所が撤去機能「そのもの」か「言及」かを見極める
- 同名の別機能・過去バージョン記述の可能性があれば「残す（要確認）」へ
- 判定理由を必ず1行で残す（人間がレビューできるように）

---

### Step 4: チェックリスト生成 (Checklist Output)

**目的**: 仕分け結果を作業可能なチェックリストとしてチャットに出力する

**出力フォーマット**:

```markdown
# 撤去影響範囲チェック: 友だち追加ボタン

検索キーワード: 友だち追加, 友達追加, addFriend, FriendAddButton
ヒット総数: 12件（削除対象 6 / 要修正 4 / 残す（要確認） 2）

## 削除対象
- [ ] src/components/FriendAddButton.tsx:1 — コンポーネント本体 — 撤去機能そのもの
- [ ] src/components/FriendAddButton.test.tsx:1 — テスト — 撤去機能専用
- [ ] locales/ja.json:42 — "friend_add.button_label" — 撤去機能専用の文言キー

## 要修正
- [ ] docs/terms.md:88 — 第5条「友だち追加機能について」 — 条項の改訂が必要
- [ ] docs/manual/profile.md:23 — プロフィール画面の説明に導線の記載 — 該当文の書き換え
- [ ] src/pages/Home.tsx:105 — 友だち追加への遷移リンク — 導線の削除と周辺レイアウト調整

## 残す（要確認）
- [ ] CHANGELOG.md:12 — リリース履歴の記載 — 履歴のため通常は残す
- [ ] src/api/friend.ts:30 — addFriend API — 他機能（QR招待）からも利用の可能性
```

---

### Step 5: 運用と完了条件 (Operation)

**実行タイミング**:

- 撤去作業の**着手前**: 影響範囲の全体像を把握し、作業計画に落とす
- **PR作成前**: 消し漏れ・直し漏れがないか最終確認する
- **課題完了前**: チェックリストが全消化されていることを確認する

**完了条件**:

- [ ] 「削除対象」「要修正」がすべてチェック済み
- [ ] 「残す（要確認）」がすべて人間によって判断済み（残す/削除/修正のいずれかに確定）
- [ ] 再実行して新規ヒットがないこと（修正中に増えた言及の検出）
